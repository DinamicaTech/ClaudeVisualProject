Map design proposals

Three different ways to draw the node hierarchy. Each page is a static mock-up with this project's own docs and a larger invented project (switch with "Data"). Click any node to see what it depends on and what uses it.

A · Branches evolution of today's map

Same left-to-right tree, drawn as cards. Each top-level area has a colour that runs through its curved connectors. Dependencies become small chips inside the card instead of repeated boxes.

Good for
Reading titles and summaries; closest to what you already validated.
Trade-off
Gets tall with many nodes; needs scrolling.

B · Orbits radial hierarchy

The project in the centre, one ring per level, one coloured sector per area. Dot size shows how many decisions a node has. Dependencies appear only for the selected node, as curves.

Good for
Seeing the whole project and its balance at a glance, even with many nodes.
Trade-off
Only titles are shown; summaries live in the side card.

C · Floor plan nested rooms

No lines at all: every node is a room that contains its children, and each top-level area is a tinted wing. Summaries and decision bars are visible in place.

Good for
Reading it like a document; works well on narrow screens.
Trade-off
Depth is less obvious beyond three levels.

Mock-ups only: they are not connected to the real viewer and do not read a docs folder.
